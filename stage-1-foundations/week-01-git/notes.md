# Неделя 1 · Git и GitHub

## Модель Git
Три зоны: working directory -> index -> repository.
Коммит это снимок, ветка это указатель на коммит, HEAD это указатель на ветку.
Ветку создать копейки стоит, это просто файлик с хешем внутри.

## merge vs rebase (спросят на собесе)
merge клеит истории новым коммитом, история кривая с вилками, хеши на месте, для общих веток ок.
rebase переписывает коммиты поверх другой вершины, линия ровная, но хеши меняются (это уже другие коммиты).
Правило: rebase у себя в ветке, в main вливаю через PR. Общие ветки не ребейзить, иначе всё задвоится.

## Команды каждый день
| Команда | Что делает |
|---|---|
| git remote add origin git@github.com:USER/REPO.git | подключить свой репозиторий как origin (куда пушу) |
| git status -s | где что лежит, использую чаще всего |
| git diff | что наделал но не заstage'ил |
| git diff --staged | что реально уйдёт в коммит |
| git add -p | собрать коммит по кускам, не всё скопом (удобно, так как можно точечно коммитить) |
| git switch -c ветка | новую ветку и сразу туда |
| git lg | граф лога (стандартный альяс под log --oneline --graph --decorate --all) |
| git commit --amend | подправить последний коммит (если не запушен) |
| git restore --staged файл | выкинуть из индекса |
| git reset --hard хэш коммита | прыгнуть в истории назад на точку предыдущих коммитов |

## Конфликты
Идёт когда обе ветки трогают одни строки. Git ставит маркеры <<<<<<< ======= >>>>>>>.
Правлю руками, сношу все маркеры, git add, потом --continue.
Если запутался — git merge/rebase --abort и всё как было.

## Как выхожу из проблем
Потерял коммит после reset --hard: git reflog, нашёл, git reset --hard HEAD@{n}. reflog имба, очень часто пользуюсь.
Отменить публичный коммит: git revert (reset для общих веток нельзя, он историю переписывает).
Надо срочно переключиться а работа недоделана: git stash -u (без -u не берёт новые файлы, наступал).

## reset по-быстрому
soft — двигает ветку, изменения в индексе.
mixed — двигает ветку, изменения в рабочей.
hard — двигает ветку и всё стирает (осторожно, так как файлы не вернуть).

## GitHub
fork — своя копия чужого репо когда нет прав пушить (опенсорс). В команде не надо, там ветки в общем репо.
PR это штука гитхаба а не git. Описание пишу: что / зачем / как проверить.
Мёржу через squash and merge — вся ветка в один коммит, main чистый.
Тег: git tag -a v0.1.0 -m "...". Сами не пушатся, надо git push origin v0.1.0.
semver: MAJOR.MINOR.PATCH. ломающее / фича / багфикс.
